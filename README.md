# АвтоВес

Программа для автомобильных весов: вес с индикатора через Moxa, распознавание номеров
с IP-камер, автоматические светофоры (и шлагбаумы), журнал рейсов, талоны, выгрузка в 1С.

Оборудование, под которое настроено:
- весы «Магистраль-2» БВ2-С-80 (НПВ 80 000 кг, НмПВ 400 кг, e = 20/50 кг);
- индикатор **CAS CI-200A**, порт **COM1 (RS-232, DB9)**;
- **Moxa NPort** (преобразователь RS-232 → Ethernet);
- **Moxa ioLogik E1214** (6 входов + 6 реле, Modbus TCP) — светофоры, шлагбаумы, ИК-барьеры;
- любые IP-камеры с RTSP (Hikvision, Dahua и т.д.).

## АвтоВес 2: выгрузки у клиентов, логист, приложение водителя

Версия 2 объединяет весовую и учёт выгрузок газа у клиентов (бывший «ГазРейс»).

- **Приложение водителя (Android).** Вход по логину и паролю один раз. Водитель выбирает машину и прицеп,
  взвешивается кнопками «Приехал на базу» / «Уехал с базы» и записывает выгрузки у клиентов в литрах.
  Выгрузки без связи хранятся в телефоне и уходят позже; взвешивание работает только при связи.
- **Кабинет логиста** (`/logist`, вход по логину и паролю; в программе оператора — вкладка «Уведомления»):
  уведомления, отчёт по выгрузкам с выгрузкой в Excel, сверка с весами, клиенты, водители, логисты.
- **Сверка с весами.** Поездка — от взвешивания «уехал» до следующего «приехал» той же машины.
  По весам отвезено = газ при выезде − газ при возврате (кг → литры по плотности из настроек газа),
  по водителю — сумма его выгрузок за это время. Нужна тара машины и прицепа в справочнике ТС.
  Допуск задаётся в `config.yaml`: `logist: {tolerance_pct: 2, tolerance_l: 100}`.
- **Уведомления:** счета клиентам-юрлицам после выгрузки, расхождения с весами, новые клиенты от водителей.

### Выход в интернет

У программы два порта. Основной (`server.port`) — рабочее место оператора, светофоры, настройки, 1С:
он остаётся только в локальной сети. Внешний (`server.public_port`, по умолчанию 8790, `0` — выключить)
отдаёт только приложение водителя и кабинет логиста — в интернет выводится только он.

На сервере Ubuntu с доменом:

```
sudo bash deploy/proxy.sh ves.example.ru 192.168.1.50:8790
```

где второй параметр — адрес компьютера с АвтоВес и его внешний порт. Скрипт ставит nginx и сертификат HTTPS.
На роутере пробрасываются только порты 80 и 443 на сервер Ubuntu; порты АвтоВес наружу не пробрасываются.

Первого логиста создают на весовой: вкладка «Уведомления» в программе оператора. Из интернета этого сделать нельзя.

### Сервер на Ubuntu

Программа и база данных могут работать на сервере Ubuntu в одной сети с весами (Moxa) и камерами,
а на компьютерах ставится только программа оператора (в установщике — «только программа оператора»,
адрес сервера `http://адрес-сервера:8780`).

```
git clone -b v2 https://github.com/alexbel692-art/avtoves.git
sudo bash avtoves/deploy/install.sh ves.example.ru
```

Скрипт ставит службу `avtoves`, nginx и сертификат HTTPS. Настройки и база лежат в `/var/lib/avtoves`
(`config.yaml`, папка `data`). Перенос с Windows: остановите службу, скопируйте туда `config.yaml` и папку `data`,
выполните `chown -R avtoves:avtoves /var/lib/avtoves` и запустите службу.

### Заказы, оплата, менеджеры

- Логист создаёт заказы (клиент, адрес, литры, водитель, дата). Водитель видит список в приложении,
  по каждому заказу записывает выгрузку или отмечает «Не получилось» с причиной.
- Клиент — юрлицо (после выгрузки менеджеру напоминание о счёте), частное лицо (водитель отмечает,
  оплатил клиент или нет; при неоплате — уведомление менеджеру) или свой объект.
- Менеджер входит в тот же кабинет и видит только своих клиентов: неоплаты, счета, выгрузки.
- Вкладка «Взвешивания» показывает фото со всех камер по каждому взвешиванию.

### Уведомления водителям через Google (Firebase)

1. В консоли Firebase создайте проект и приложение Android с именем пакета `ru.avtoves.driver`.
2. Файл `google-services.json` сохраните в секрет репозитория `GOOGLE_SERVICES_JSON` и пересоберите приложение.
3. Ключ сервисного аккаунта (Настройки проекта → Сервисные аккаунты → Создать закрытый ключ) положите на сервер
   как `firebase.json` в папку данных (на Ubuntu: `/var/lib/avtoves/data/firebase.json`) и перезапустите службу.

Без этого заказы приходят в приложение, когда оно открыто.

### Топливо по ДУТ из Ставтрэка

Вкладка «Ставтрэк» в кабинете логиста-администратора: адрес API (`https://wiafleet.online/api`), логин и пароль
учётной записи Ставтрэка (лучше отдельной, с правами только на просмотр). При каждом взвешивании программа
запрашивает последнюю позицию машины и сохраняет уровень топлива по ДУТ. В сверке с весами топливо, сожжённое
за рейс, вычитается из «отвезённого газа» (плотность топлива задаётся там же). Машина привязывается к устройству
по госномеру в названии или вручную; кнопка «Проверить связь и ДУТ» показывает текущие показания.

### Карта и маршруты

Вкладка «Карта» показывает машины по данным Ставтрэка, клиентов с найденными координатами и базу.

Вкладка «Маршруты» (логист-администратор): ключи Яндекс Геокодера и Яндекс Матрицы расстояний, адрес базы.
Координаты клиента находятся по адресу при сохранении; если адрес нашёлся неточно, координаты можно задать вручную.
Кнопка «Рассчитать маршрут» на вкладке «Заказы» расставляет заказы водителя на день в лучшем порядке
(с базы и обратно, по времени в пути с пробками); водитель видит этот порядок в приложении и может открыть
адрес в навигаторе. Один расчёт для N заказов запрашивает у Яндекса (N+1)² ячеек матрицы.

## Как работает цикл

1. Весы пустые → светофоры **зелёные** на въезд (в тупиковом режиме — только сторона А).
2. Машина подъезжает — камера читает номер несколько раз в секунду, номера копятся.
3. Вес > 400 кг → оба светофора **красные**.
4. Вес стабилен 3 с (и флаг ST индикатора) и ИК-барьеры свободны → вес **фиксируется**:
   снимки со всех камер, вырезка номера, запись в базу.
5. Загорается **зелёный на выезд** (противоположная сторона для проездных весов),
   импульс на шлагбаум, если он подключён.
6. Вес < 200 кг 3 секунды → весы свободны, снова зелёный на въезд.

**Рейсы.** Первое взвешивание машины открывает рейс. Второе взвешивание той же машины
(в пределах 24 ч) закрывает его: брутто = больший вес, тара = меньший, нетто = разница.
Направление определяется само: сначала гружёная — ввоз, сначала пустая — вывоз.
Рейс с одним взвешиванием можно закрыть по таре из справочника ТС.

**Выбор номера.** Для машины берутся прочтения за 60 с до заезда. Номера машин,
которые уже взвешены за это время, исключаются; выигрывает номер с наибольшей
уверенностью, свежестью и правильным форматом РФ. Оператор всегда может ввести номер
вручную до фиксации или исправить его в журнале после.

## Подключение оборудования

### Индикатор CAS CI-200A → Moxa NPort
- Кабель: COM1 индикатора (DB9) → порт NPort. Обычно TX/RX нужно перекрестить
  (контакты 2↔3, 5 — земля), как нуль-модем.
- В настройках индикатора включите **непрерывную передачу (поток)** на COM1,
  скорость 9600, 8N1 (номера F-функций смотрите в паспорте CI-200A: режим передачи,
  скорость, чётность).
- NPort (веб-интерфейс): Serial Settings — 9600, 8, None, 1, Flow control None;
  Operating Settings — **TCP Server**, Local TCP port **4001**.
- В `config.yaml`: `scale.connection: tcp://<IP NPort>:4001`.
  Если NPort в режиме Real COM (с драйвером): `serial://COM5?baud=9600`.

Проверка: вкладка **Диагностика** показывает сырые строки от индикатора.
Должно приходить что-то вроде `ST,GS,...+  12340 kg`. Если формат другой —
поставьте `parser: generic` (берётся последнее число в строке).

### Светофоры → модуль реле: Moxa ioLogik E1214 или ОВЕН МК210-301

Модуль выбирается в «Настройки → Светофоры → Модуль». Номера выходов вводятся так, как подписаны
на корпусе: у Moxa — R0…R5 и входы DI0…DI5, у ОВЕН МК210-301 — DO1…DO8 и входы DI1…DI6
(по умолчанию у ОВЕН: DO1/DO2 — А красный/зелёный, DO3/DO4 — Б красный/зелёный).
ОВЕН управляется битовой маской в регистре 470 (состояние — 468, входы — 51); если в вашей прошивке
адреса другие, их можно поменять там же. Для улицы у обоих модулей есть исполнение до −40 °C
(Moxa — версия E1214-T, ОВЕН МК210-301 — штатно), ставятся в шкаф с подогревом.

#### Moxa ioLogik E1214
Реле ioLogik коммутируют светофоры (через промежуточные реле/контакторы, если
светофоры 220 В и мощнее допустимого для реле модуля).

| Реле | Назначение          |
|------|---------------------|
| R0   | Сторона А, красный  |
| R1   | Сторона А, зелёный  |
| R2   | Сторона Б, красный  |
| R3   | Сторона Б, зелёный  |
| R4   | Шлагбаум А (опц.)   |
| R5   | Шлагбаум Б (опц.)   |

Входы DI0/DI1 — ИК-барьеры по краям платформы (опционально). Если барьер перекрыт,
вес не фиксируется: машина стоит не полностью.

Номера реле и входов меняются в `config.yaml` (раздел `io`). Модуль раз в 0,5 с
переподтверждает состояние, так что после перезагрузки модуля светофоры восстановятся.
При потере связи с весами светофоры на въезд ставятся в красный.

### Камеры
Две камеры — по одной на каждый въезд, смотрят на передний номер подъезжающей машины.
Для Hikvision: `rtsp://user:pass@IP:554/Streaming/Channels/101`,
для Dahua: `rtsp://user:pass@IP:554/cam/realmonitor?channel=1&subtype=0`.
Лучше всего: номер в кадре шириной от 150 пикселей, без засветки фарами
(включите WDR/BLC, ночью — ИК-подсветка).

Распознавание — локальное, на процессоре (fast-alpr: детектор YOLOv9 + OCR),
без облака и подписок. Модели скачиваются один раз при установке.

## Установка на Windows

Нужен компьютер с Windows 10/11 или Windows Server 2016+ (x64) в одной сети с Moxa и камерами.
Python и другие программы ставить не нужно — всё внутри установщика.

1. Запустите **AvtoVes-Setup-<версия>.exe** (нужны права администратора).
2. Мастер спросит:
   - IP-адрес и порт **Moxa NPort** (весы), IP **Moxa ioLogik** (светофоры, можно оставить пустым);
   - порт АвтоВес в сети (по умолчанию **8780**; мастер проверит, что он не занят другой программой);
   - RTSP-адреса камер въездов А и Б (можно оставить пустыми);
   - режим: проездные или тупиковые весы;
   - галочка «Режим проверки без оборудования» — чтобы посмотреть программу без весов.
3. Установщик:
   - ставит АвтоВес в `C:\Program Files\AvtoVes`;
   - создаёт **службу Windows «АвтоВес»** (запуск вместе с компьютером, сама перезапускается при сбое);
   - открывает доступ в брандмауэре, чтобы интерфейс открывался с других компьютеров;
   - добавляет ярлыки в меню «Пуск» → АвтоВес (и на рабочий стол, если выбрано).
4. В конце запустится программа **АвтоВес** — отдельное окно со своей иконкой, без браузера.

**Два варианта установки** (выбираются в начале мастера):
- **Сервер весовой** — на компьютер весовой: служба, весы, камеры, светофоры и программа оператора.
- **Только программа оператора** — на другие компьютеры (бухгалтерия, охрана, RDP-сервер):
  ставится только окно АвтоВес, мастер спросит адрес сервера (например `192.168.1.10:8780`).

Программа АвтоВес открывает интерфейс в своём окне (движок Microsoft WebView2, как в Edge;
на Windows 10/11 он уже есть, на Windows Server установщик поставит его сам при наличии интернета,
а без него программа откроется окном Microsoft Edge). Повторный запуск разворачивает уже открытое окно,
размер окна запоминается, F11 — во весь экран, Ctrl + колесо — масштаб. Если сервер недоступен,
программа показывает «Подключение к серверу…» и подключается сама, как только он появится.

**Порт.** Если порт занят другой программой на этом компьютере (например, детектором людей),
при обновлении АвтоВес сам переедет на свободный (8780, 8781…) и сообщит об этом.
Программа АвтоВес на сервере подключится сама; на других компьютерах и в 1С укажите новый порт.
Сменить порт: АвтоВес → «Настройки» → «Сеть, 1С и доступ» → порт → «Сохранить» → «Перезапустить».

## Пароль оператора

«Настройки → Сеть, 1С и доступ → Пароль оператора — вход в программу». Когда он задан, рабочее место
(экран оператора, журнал, справочники, талоны, фото, Excel) открывается только после входа; вход запоминается
на 30 дней, кнопка «Выйти» — вверху. Смена пароля сразу закрывает все старые входы.
Без пароля оператора работают только: страница водителей `/driver` (по их PIN), выгрузка в 1С (по токену)
и проверка доступности сервера. Водитель видит фото только своих взвешиваний.
Отдельно можно поставить «Пароль на настройки» — чтобы оператор не менял адреса оборудования.

## Без распознавания номеров и без светофоров

- «Настройки → Распознавание номеров» → снимите «распознавать номера по камерам». Камеры остаются и
  фотографируют машину при каждом взвешивании (подходит для боковых камер, которые не видят номер);
  номер вводит оператор или выбирает водитель на телефоне. Процессор не тратится на распознавание.
- «Настройки → Светофоры» → снимите «светофоры подключены». Панель светофоров на экране оператора скрывается.

Включаются обратно теми же галочками, без переустановки.

## Водители взвешиваются сами с телефона

1. «Настройки → Проезд и взвешивание» → включите **«водители взвешиваются сами с телефона»**.
   Тогда вес записывается только по кнопке водителя (или кнопке оператора), автоматической фиксации нет.
2. Вкладка **«Водители»**: добавьте водителей — ФИО, телефон, машина по умолчанию и **PIN (4–8 цифр,
   у каждого свой)**. PIN в базе не хранится (только его отпечаток); забытый PIN оператор просто задаёт заново.
3. Там же — ссылка для водителей вида `http://<IP сервера>:8780/driver` и QR-код. Распечатайте QR и повесьте
   на весовой. Телефон водителя должен быть в **Wi-Fi весовой** (внутренняя сеть).
4. Водитель открывает страницу, вводит PIN (вход запоминается на 30 дней), выбирает машину и, стоя на весах,
   нажимает **«Приехал на базу»** или **«Уехал с базы»**.

Программа ждёт, пока вес успокоится, проверяет, что машина стоит на платформе целиком (ИК-барьеры) и что
**камера видит именно эту машину** (если камера уверенно читает другой номер — взвешивание не записывается),
сохраняет вес, время и фото с камер, переключает светофор на выезд. «Приехал» открывает рейс, «Уехал» закрывает
его: в журнале — нетто и, для газовозов, сколько газа слито/залито. Водитель видит результат с фото и свои
взвешивания за день; в журнале у взвешивания видно, какой водитель нажал (📱).

Защита: 5 неверных PIN подряд с одного телефона — блокировка на 5 минут; отключённый водитель («работает» —
снять галочку) сразу теряет доступ.

## Тягачи, прицепы и одиночки

В «Справочнике ТС» у каждой записи есть **тип**:

- **Одиночка** — машина без прицепа, в том числе с бочками на борту. Тара — вес пустой машины с пустыми бочками,
  «объём бочек / цистерны» — общий объём бочек.
- **Тягач** — ездит с прицепом или полуприцепом. Тара — вес самого тягача.
- **Прицеп / полуприцеп** — отдельная запись со своим номером, тарой и объёмом цистерны.

Водитель на телефоне выбирает машину; если это **тягач** — появляется второй список «Прицеп / полуприцеп»
(или «без прицепа», или «другой прицеп…»). Для одиночки прицеп не спрашивается. Оператор может вписать прицеп
рядом с номером машины на экране оператора. В журнале, талоне, Excel и выгрузке 1С номер показывается как
«машина + прицеп».

Газ для сцепки считается от **тары тягача + тары прицепа**, процент заполнения — по объёму цистерны прицепа.
Кнопка «Пустая — запомнить тару» на сцепке: если тара тягача уже известна, программа сама вычислит тару прицепа
(и наоборот).

## Газовозы: сколько газа в машине

Для газовозов АвтоВес считает газ по разнице с **тарой пустой машины**:

- **газ при въезде** = вес на въезде − тара;
- **газ при выезде** = вес на выезде − тара;
- **слито** (или **залито**) = разница между ними.

Килограммы пересчитываются в литры по плотности из настроек (по умолчанию 0,54 кг/л для СУГ;
поставьте значение из паспорта продукции). Если в справочнике указан **объём цистерны**, показывается
и процент заполнения.

Тару пустой машины можно:
- ввести в **«Справочнике ТС»** (поле «Тара пустой, кг»);
- или в журнале открыть рейс → у взвешивания пустой машины нажать **«Пустая — запомнить тару»**.
  Газ по прошлым рейсам этой машины досчитается сам.

Газ виден на экране оператора после взвешивания, в журнале (колонки «Газ въезд/выезд», «Слито/залито»
и итог за период), в талоне, в Excel и в выгрузке для 1С (поле `gas`). Включается и выключается
в «Настройки → Газовозы».

## Настройки в программе

Все настройки меняются в программе: **АвтоВес → вкладка «Настройки»** (или ярлык «Настройки АвтоВес»
в «Пуск»). Править файл руками не нужно.

- **Весы** — IP-адрес и порт Moxa NPort (или COM-порт), формат данных индикатора, пороги
  «машина на весах» / «весы свободны», время и допуск стабилизации.
  Кнопка **«Проверить связь с весами»** показывает текущий вес и строки, которые присылает индикатор.
- **Светофоры** — IP ioLogik, номера реле для красного/зелёного каждой стороны и шлагбаумов,
  ИК-барьеры. **«Проверить связь с ioLogik»** показывает состояние реле и входов, кнопки **R0…R5**
  включают реле на 2 секунды — удобно найти, какой светофор на каком реле.
- **Камеры** — добавить/удалить, название, сторона въезда, RTSP-адрес, распознавать ли номера.
  **«Проверить»** показывает кадр с камеры.
- **Проезд** — проездные или тупиковые весы, автофиксация веса, время ожидания.
- **Сеть, 1С и доступ** — порт АвтоВес, токен для 1С (кнопка «Новый»), **пароль на настройки**
  (чтобы операторы не меняли адреса оборудования), режим проверки без оборудования.

«Сохранить и применить» — настройки вступают в силу сразу, без перезапуска службы
(текущий цикл взвешивания сбрасывается, поэтому сохраняйте, когда весы свободны).
Только смена порта требует перезапуска — программа предложит его сама.
Предыдущая версия настроек сохраняется рядом: `config.yaml.bak`.

**Ярлыки в «Пуск» → АвтоВес:** АвтоВес, Настройки АвтоВес, Перезапустить АвтоВес,
Данные и снимки, Журналы, Обмен с 1С, Инструкция, Удалить.
На компьютерах с «только программой оператора» — АвтоВес, Настройки АвтоВес, Инструкция, Удалить.

**Где что лежит:**
- программа — `C:\Program Files\AvtoVes`;
- настройки — `C:\ProgramData\AvtoVes\config.yaml`;
- база взвешиваний — `C:\ProgramData\AvtoVes\data\avtoves.db`, снимки — `data\snapshots\ГГГГ-ММ-ДД\`;
- журналы — `C:\ProgramData\AvtoVes\data\avtoves.log` и `C:\ProgramData\AvtoVes\logs\`.

**Обновление:** запустите установщик новой версии поверх. Вопросы не задаются,
настройки, база и снимки сохраняются, служба перезапускается. Более старую версию поверх
новой поставить нельзя (защита от отката; осознанно — ключ `/ALLOWDOWNGRADE`).

**Удаление:** «Программы и компоненты» → АвтоВес. Служба и правило брандмауэра удаляются,
а базу и снимки установщик предложит оставить (по умолчанию — оставить).

**Тихая установка** (для нескольких компьютеров):
```
rem сервер весовой
AvtoVes-Setup-1.0.0.exe /VERYSILENT /NPORT=192.168.1.50 /NPORTPORT=4001 /IOLOGIK=192.168.1.60 /PORT=8780 /CAMA="rtsp://..." /CAMB="rtsp://..." /MODE=through
rem только программа оператора
AvtoVes-Setup-1.0.0.exe /VERYSILENT /TYPE=client /SERVER=192.168.1.10:8780
```

## Сборка установщика

Установщик собирается из этой папки (как Ласточка — Inno Setup).

- **На GitHub (как Ласточка):** положите проект в репозиторий, вкладка Actions →
  «АвтоВес — установщик Windows» → Run workflow → версия. Сборка сама проверяет установщик
  на чистой Windows: тихая установка, служба запустилась, проезд машины записался,
  обновление поверх сохранило базу, удаление убрало службу. Готовый `.exe` — в Releases.
- **На любом компьютере с Windows:** двойной щелчок по `Собрать установщик для Windows.bat`.
  Нужны интернет и Python 3.10+ (только для сборки: `winget install Python.Python.3.12`);
  Inno Setup поставится сам. Результат — в папке `dist`.

Разработка и проверка без Windows: `pip install -r requirements.txt`, затем
`python main.py --simulate` → http://localhost:8780.

## Обмен с 1С

- `GET /api/1c/trips?only_new=1` — закрытые рейсы, ещё не загруженные в 1С (JSON).
  Заголовок `X-Api-Token: <api_token>`.
- `POST /api/1c/ack` с телом `{"ids":[1,2,3]}` — отметить рейсы загруженными.
  Если рейс потом исправили в журнале, он снова попадёт в выгрузку.

Готовый код для 1С: `1c\ЗагрузкаВзвешиваний.bsl` — получает рейсы, вызывает
`ОбработатьРейс()` (там пример записи в регистр сведений) и подтверждает загрузку.
Подходит для регламентного задания раз в 1–5 минут.

## Вкладки интерфейса

- **Оператор** — табло веса, состояние, номер с вырезкой, ручной ввод номера,
  кнопка «Зафиксировать вес» (если автофиксация выключена или нужно вручную),
  светофоры с ручным управлением, видео с камер, события.
- **Журнал** — рейсы за период, поиск по номеру машины или прицепа, редактирование (груз, контрагент,
  водитель, прицеп), печать талона, выгрузка в Excel. Справа — **фото рейса**: щёлкните строку, и рядом
  появятся взвешивания (приезд/убытие, вес, кто нажал) с фото с камер; щелчок по фото — во весь экран.
- **Справочник ТС** — одиночки, тягачи и прицепы, контрагенты, водители, известная тара, объём ёмкостей, стоп-лист.

Внизу боковой панели — переключатель светлой и тёмной темы.
- **Диагностика** — связь с оборудованием, сырые строки индикатора, имитатор.

### Сводка, Яндекс Карты и машины из Ставтрэка

- **Сводка** — первая страница кабинета: слито сегодня и за 14 дней, заказы на сегодня, машины в рейсе, сколько выгрузок ждут счёта и оплаты, диаграммы по дням, клиентам и водителям. Менеджер видит только своих клиентов.
- **Яндекс Карты** — «Маршруты» → «Настроить» → «Карта в кабинете: Яндекс Карты» и ключ «JavaScript API и HTTP Геокодер» из кабинета разработчика Яндекса. В настройках ключа у Яндекса ограничьте его адресом своего сайта: этот ключ по своей природе виден в браузере. Без ключа показывается OpenStreetMap.
- **Машины из Ставтрэка** — «Ставтрэк» → «Загрузить машины из Ставтрэка»: список устройств, которых ещё нет в справочнике; отметьте нужные, проверьте госномер и тип. Машина добавляется в справочник ТС и сразу привязывается к своему устройству. Прицепы и тару добавляют в программе оператора.
