# АвтоВес

Программа для автомобильных весов: вес с индикатора через Moxa, распознавание номеров
с IP-камер, автоматические светофоры (и шлагбаумы), журнал рейсов, талоны, выгрузка в 1С.

Оборудование, под которое настроено:
- весы «Магистраль-2» БВ2-С-80 (НПВ 80 000 кг, НмПВ 400 кг, e = 20/50 кг);
- индикатор **CAS CI-200A**, порт **COM1 (RS-232, DB9)**;
- **Moxa NPort** (преобразователь RS-232 → Ethernet);
- **Moxa ioLogik E1214** (6 входов + 6 реле, Modbus TCP) — светофоры, шлагбаумы, ИК-барьеры;
- любые IP-камеры с RTSP (Hikvision, Dahua и т.д.).

## Как работает цикл

1. Весы пустые → светофоры **зелёные** на въезд (в тупиковом режиме — только сторона А).
2. Машина подъезжает — камера читает номер несколько раз в секунду, номера копятся.
3. Вес > 400 кг → оба светофора **красные**.
4. Вес стабилен 3 с (и флаг ST индикатора) и ИК-барьеры свободны → вес **фиксируется**:
   снимки со всех камер, вырезка номера, запись в базу.
5. Загорается **зелёный на выезд** (противоположная сторона для проездных весов),
   импульс на шлагбаум, если он подключён.
6. Вес < 200 кг 3 секунды → весы свободны, снова зелёный на въезд.

**Рейсы.** Первое взвешивание машины открывает рейс. Второе взвешивание той же машины
(в пределах 24 ч) закрывает его: брутто = больший вес, тара = меньший, нетто = разница.
Направление определяется само: сначала гружёная — ввоз, сначала пустая — вывоз.
Рейс с одним взвешиванием можно закрыть по таре из справочника ТС.

**Выбор номера.** Для машины берутся прочтения за 60 с до заезда. Номера машин,
которые уже взвешены за это время, исключаются; выигрывает номер с наибольшей
уверенностью, свежестью и правильным форматом РФ. Оператор всегда может ввести номер
вручную до фиксации или исправить его в журнале после.

## Подключение оборудования

### Индикатор CAS CI-200A → Moxa NPort
- Кабель: COM1 индикатора (DB9) → порт NPort. Обычно TX/RX нужно перекрестить
  (контакты 2↔3, 5 — земля), как нуль-модем.
- В настройках индикатора включите **непрерывную передачу (поток)** на COM1,
  скорость 9600, 8N1 (номера F-функций смотрите в паспорте CI-200A: режим передачи,
  скорость, чётность).
- NPort (веб-интерфейс): Serial Settings — 9600, 8, None, 1, Flow control None;
  Operating Settings — **TCP Server**, Local TCP port **4001**.
- В `config.yaml`: `scale.connection: tcp://<IP NPort>:4001`.
  Если NPort в режиме Real COM (с драйвером): `serial://COM5?baud=9600`.

Проверка: вкладка **Диагностика** показывает сырые строки от индикатора.
Должно приходить что-то вроде `ST,GS,...+  12340 kg`. Если формат другой —
поставьте `parser: generic` (берётся последнее число в строке).

### Светофоры → Moxa ioLogik E1214
Реле ioLogik коммутируют светофоры (через промежуточные реле/контакторы, если
светофоры 220 В и мощнее допустимого для реле модуля).

| Реле | Назначение          |
|------|---------------------|
| R0   | Сторона А, красный  |
| R1   | Сторона А, зелёный  |
| R2   | Сторона Б, красный  |
| R3   | Сторона Б, зелёный  |
| R4   | Шлагбаум А (опц.)   |
| R5   | Шлагбаум Б (опц.)   |

Входы DI0/DI1 — ИК-барьеры по краям платформы (опционально). Если барьер перекрыт,
вес не фиксируется: машина стоит не полностью.

Номера реле и входов меняются в `config.yaml` (раздел `io`). Модуль раз в 0,5 с
переподтверждает состояние, так что после перезагрузки модуля светофоры восстановятся.
При потере связи с весами светофоры на въезд ставятся в красный.

### Камеры
Две камеры — по одной на каждый въезд, смотрят на передний номер подъезжающей машины.
Для Hikvision: `rtsp://user:pass@IP:554/Streaming/Channels/101`,
для Dahua: `rtsp://user:pass@IP:554/cam/realmonitor?channel=1&subtype=0`.
Лучше всего: номер в кадре шириной от 150 пикселей, без засветки фарами
(включите WDR/BLC, ночью — ИК-подсветка).

Распознавание — локальное, на процессоре (fast-alpr: детектор YOLOv9 + OCR),
без облака и подписок. Модели скачиваются один раз при установке.

## Установка на Windows

Нужен компьютер с Windows 10/11 или Windows Server 2016+ (x64) в одной сети с Moxa и камерами.
Python и другие программы ставить не нужно — всё внутри установщика.

1. Запустите **AvtoVes-Setup-<версия>.exe** (нужны права администратора).
2. Мастер спросит:
   - IP-адрес и порт **Moxa NPort** (весы), IP **Moxa ioLogik** (светофоры, можно оставить пустым);
   - порт АвтоВес в сети (по умолчанию **8780**; мастер проверит, что он не занят другой программой);
   - RTSP-адреса камер въездов А и Б (можно оставить пустыми);
   - режим: проездные или тупиковые весы;
   - галочка «Режим проверки без оборудования» — чтобы посмотреть программу без весов.
3. Установщик:
   - ставит АвтоВес в `C:\Program Files\AvtoVes`;
   - создаёт **службу Windows «АвтоВес»** (запуск вместе с компьютером, сама перезапускается при сбое);
   - открывает доступ в брандмауэре, чтобы интерфейс открывался с других компьютеров;
   - добавляет ярлыки в меню «Пуск» → АвтоВес (и на рабочий стол, если выбрано).
4. В конце запустится программа **АвтоВес** — отдельное окно со своей иконкой, без браузера.

**Два варианта установки** (выбираются в начале мастера):
- **Сервер весовой** — на компьютер весовой: служба, весы, камеры, светофоры и программа оператора.
- **Только программа оператора** — на другие компьютеры (бухгалтерия, охрана, RDP-сервер):
  ставится только окно АвтоВес, мастер спросит адрес сервера (например `192.168.1.10:8780`).

Программа АвтоВес открывает интерфейс в своём окне (движок Microsoft WebView2, как в Edge;
на Windows 10/11 он уже есть, на Windows Server установщик поставит его сам при наличии интернета,
а без него программа откроется окном Microsoft Edge). Повторный запуск разворачивает уже открытое окно,
размер окна запоминается, F11 — во весь экран, Ctrl + колесо — масштаб. Если сервер недоступен,
программа показывает «Подключение к серверу…» и подключается сама, как только он появится.

**Порт.** Если порт занят другой программой на этом компьютере (например, детектором людей),
при обновлении АвтоВес сам переедет на свободный (8780, 8781…) и сообщит об этом.
Программа АвтоВес на сервере подключится сама; на других компьютерах и в 1С укажите новый порт.
Сменить порт вручную: «Настройки АвтоВес» → `server: port:` → «Перезапустить АвтоВес».

**Ярлыки в «Пуск» → АвтоВес:** АвтоВес (интерфейс), Настройки, Перезапустить АвтоВес
(после правки настроек), Данные и снимки, Журналы, Обмен с 1С, Инструкция, Удалить.
На компьютерах с «только программой оператора» — АвтоВес, Инструкция, Удалить.

**Где что лежит:**
- программа — `C:\Program Files\AvtoVes`;
- настройки — `C:\ProgramData\AvtoVes\config.yaml`;
- база взвешиваний — `C:\ProgramData\AvtoVes\data\avtoves.db`, снимки — `data\snapshots\ГГГГ-ММ-ДД\`;
- журналы — `C:\ProgramData\AvtoVes\data\avtoves.log` и `C:\ProgramData\AvtoVes\logs\`.

**Обновление:** запустите установщик новой версии поверх. Вопросы не задаются,
настройки, база и снимки сохраняются, служба перезапускается. Более старую версию поверх
новой поставить нельзя (защита от отката; осознанно — ключ `/ALLOWDOWNGRADE`).

**Удаление:** «Программы и компоненты» → АвтоВес. Служба и правило брандмауэра удаляются,
а базу и снимки установщик предложит оставить (по умолчанию — оставить).

**Тихая установка** (для нескольких компьютеров):
```
rem сервер весовой
AvtoVes-Setup-1.0.0.exe /VERYSILENT /NPORT=192.168.1.50 /NPORTPORT=4001 /IOLOGIK=192.168.1.60 /PORT=8780 /CAMA="rtsp://..." /CAMB="rtsp://..." /MODE=through
rem только программа оператора
AvtoVes-Setup-1.0.0.exe /VERYSILENT /TYPE=client /SERVER=192.168.1.10:8780
```

## Сборка установщика

Установщик собирается из этой папки (как Ласточка — Inno Setup).

- **На GitHub (как Ласточка):** положите проект в репозиторий, вкладка Actions →
  «АвтоВес — установщик Windows» → Run workflow → версия. Сборка сама проверяет установщик
  на чистой Windows: тихая установка, служба запустилась, проезд машины записался,
  обновление поверх сохранило базу, удаление убрало службу. Готовый `.exe` — в Releases.
- **На любом компьютере с Windows:** двойной щелчок по `Собрать установщик для Windows.bat`.
  Нужны интернет и Python 3.10+ (только для сборки: `winget install Python.Python.3.12`);
  Inno Setup поставится сам. Результат — в папке `dist`.

Разработка и проверка без Windows: `pip install -r requirements.txt`, затем
`python main.py --simulate` → http://localhost:8780.

## Обмен с 1С

- `GET /api/1c/trips?only_new=1` — закрытые рейсы, ещё не загруженные в 1С (JSON).
  Заголовок `X-Api-Token: <api_token>`.
- `POST /api/1c/ack` с телом `{"ids":[1,2,3]}` — отметить рейсы загруженными.
  Если рейс потом исправили в журнале, он снова попадёт в выгрузку.

Готовый код для 1С: `1c\ЗагрузкаВзвешиваний.bsl` — получает рейсы, вызывает
`ОбработатьРейс()` (там пример записи в регистр сведений) и подтверждает загрузку.
Подходит для регламентного задания раз в 1–5 минут.

## Вкладки интерфейса

- **Оператор** — табло веса, состояние, номер с вырезкой, ручной ввод номера,
  кнопка «Зафиксировать вес» (если автофиксация выключена или нужно вручную),
  светофоры с ручным управлением, видео с камер, события.
- **Журнал** — рейсы за период, поиск по номеру, редактирование (груз, контрагент,
  водитель), снимки, печать талона, выгрузка в Excel.
- **Справочник ТС** — машины, контрагенты, водители, известная тара, стоп-лист.
- **Диагностика** — связь с оборудованием, сырые строки индикатора, имитатор.
